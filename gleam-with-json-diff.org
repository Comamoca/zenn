** 訂正: 「jasperは動くようになっている」は誤りだった

第1回検証時、jasperのhexdocsトップページ(=jasper.hexdocs.pm/=、最新バージョンのドキュメントを表示)

という一文を追加した。★実機で =gleam add= / =gleam build= / Hex API を確認した結果、
*これは誤りで、jasperは現在も通常のプロジェクトでは動かない*。

*** 実測結果

1. ★通常通り =gleam new= したプロジェクト(=gleam_stdlib = ">= 1.0.0 and < 2.0.0"=)で
   =gleam add jasper= すると、*2.0.1ではなく1.2.0が解決される*。
2. ★Hex APIで確認すると、原因はjasper自体のバージョン制約:

   | jasperのバージョン | =gleam_stdlib= 要求範囲                  | 現行stdlib(1.0.5)と両立するか |
   |--------------------+---------------------------------------------+--------------------------------|
   | 2.0.1 (最新, 2025-09-04) | =>= 0.62.1 and < 1.0.0=                | ✗ (1.0未満に固定されており明らかに範囲更新漏れ) |
   | 1.2.0 (2024-03-25)      | =~> 0.34 or ~> 1.0=                    | ○ (制約上は満たす)              |

   ★実際に =jasper = "2.0.1"= を =gleam.toml= に固定すると:
   #+begin_example
   error: Dependency resolution failed
   There's no compatible version of `gleam_stdlib`:
     - You require jasper 2.0.1
       - jasper requires gleam_stdlib >= 0.62.1 and < 1.0.0
     - You require gleam_stdlib >= 1.0.0 and < 2.0.0
   #+end_example

3. ★では実際に解決される1.2.0は動くのか？ → *動かない*。
   依存先の =pears 0.4.0=(2024-07-16以降更新なし)が =gleam/iterator= をimportしており、
   このモジュールは現行stdlibには存在しない(=gleam/yielder=に改名の上で削除済み)。
   #+begin_example
   error: Unknown module
     ┌─ .../pears/src/pears/input.gleam:4:1
     │
   4 │ import gleam/iterator
     │ ^^^^^^^^^^^^^^^^^^^^^
   No module has been found with the name `gleam/iterator`.
   #+end_example

*** 結論

*jasperは現在、通常のプロジェクトでは =gleam add jasper= すらまともに使えない。*
理由は記事が挙げていた「=list.at= 削除」ではなく、
- 2.0.1系: パッケージのバージョン制約が1.0未満のstdlibに固定されたまま更新されていない(=jasper=側の不備)
- 1.2.0系(実際に解決される方): 依存先=pears=が=gleam/iterator=依存のまま放置されている

という2つの独立した理由による。★なお =gleam_stdlib= を手動で
=">= 0.62.1 and < 1.0.0"= まで下げて =jasper = "2.0.1"= を明示指定すれば
=jasper.parse=/=jasper.query= の新APIは実際に動作することを確認したが、
これはプロジェクト全体を1.0未満の古いstdlibへ固定する必要がある非標準的な回避策であり、
「素直に=gleam add jasper=すれば動く」状態では全くない。

* 今回の更新で残っている問題

** 【要修正】デコード節のコードに =import gleam/dynamic/decode= が抜けている

L129-144 の =decode= 関数は =decode.field= / =decode.string= / =decode.success= を使うが、
コードブロック内にimportが書かれていない(記事冒頭L44の =import gleam/json= のみ)。

★実機で検証: importなしでコンパイルすると、=decode= というトップレベル関数名と
=gleam/dynamic/decode= モジュールの名前が衝突するのではなく、
*モジュールをimportしていないため =decode.field= が「自分自身(定義中の=decode=関数)のfieldアクセス」と
解釈され* 以下のエラーになる。

#+begin_example
error: Unknown record field
21 │     use favorites <- decode.field("favorites", favorites_decoder)
   │                             ^^^^^ This field does not exist
The value being accessed has this type:
    fn(String) -> Result(a, json.DecodeError)
#+end_example

★ =import gleam/dynamic/decode= を先頭に追加すると *警告ゼロでコンパイル・実行でき*、
出力も =Idol("arisu", 12, Favorites("game", "strawberry"))= と期待通りになることを確認済み。
なお、トップレベル関数名 =decode= とモジュール別名 =decode= が衝突する心配はない
(importさえあれば問題なく共存する)。

*** 対応案

コードブロックの先頭に以下を追加:

#+begin_src gleam
import gleam/dynamic/decode
import gleam/json
#+end_src

** 【要修正・新規】L126 =import gleam/dynamic/decocde= はタイプミス

正しくは =decode= だが =decocde= になっている(=c=と=d=が入れ替わっている)。

#+begin_example

   │                             ^^^^^ This field does not exist

    fn(String) -> Result(a, json.DecodeError)
#+end_example

*つまり今回の修正はタイプミス1文字によって実質的に無効化されている。*

** 【要修正・新規】jasperのコード例、importを減らしすぎて =Root=/=Key=/=Index=/=String= が未解決
